# Deploying to Vercel

This guide deploys the whole project on **Vercel** (free Hobby plan) with the database on **MongoDB Atlas** (free M0 cluster). Allow about 30 minutes the first time.

---

## How the deployment works

You create **two Vercel projects from the same GitHub repository**:

| Vercel project | Root directory | What it runs | Example URL |
|---|---|---|---|
| Backend | `backend` | The Express API, as a Vercel Function | `https://store-api-xyz.vercel.app` |
| Frontend | `frontend` | The built React app (static files) | `https://store-xyz.vercel.app` |

```
Browser ──► https://store-xyz.vercel.app            (frontend project)
              │
              ├─ /products, /login …  → index.html (React app)
              │
              └─ /api/*  ──proxy──►  https://store-api-xyz.vercel.app/api/*   (backend project)
                                            │
                                            └──► MongoDB Atlas
```

The frontend **proxies** every `/api/*` request to the backend (configured in `frontend/vercel.json`). The browser therefore only ever talks to the frontend's domain, so:

- The refresh token cookie is a normal first-party cookie. Every browser accepts it, including Safari, which blocks third-party cookies.
- There are no cross-origin requests from the browser, so CORS can't get in the way.

> **Why not call the backend URL directly?** Every `*.vercel.app` subdomain counts as a separate site. A cookie set by `store-api-xyz.vercel.app` for a page on `store-xyz.vercel.app` would be a third-party cookie, and Safari would drop it: users would be logged out on every page reload.

## Step 0 — What you need

- A **GitHub** account: https://github.com
- A **Vercel** account: https://vercel.com/signup (sign up with GitHub; it makes importing easier)
- A **MongoDB Atlas** account: https://www.mongodb.com/cloud/atlas/register
- The project working locally (see the README)

## Step 1 — Push the code to GitHub

1. Create a new **empty** repository on GitHub (no README, no .gitignore). Example name: `ecomm-sheryians`.
2. In the project folder, check that no secrets will be committed:

   ```bash
   git status
   git check-ignore backend/.env frontend/.env
   ```

   The second command must print both paths. That means they are ignored and won't be uploaded.

3. Commit and push:

   ```bash
   git add .
   git commit -m "E-commerce auth and product CRUD"
   git branch -M main
   git remote add origin https://github.com/<your-username>/ecomm-sheryians.git
   git push -u origin main
   ```

4. Open the repository on GitHub and confirm there is **no** `.env` file, only `.env.example`.

---

## Step 2 — Create the MongoDB Atlas database

### 2.1 Create a cluster
1. Log in to https://cloud.mongodb.com.
2. Create a project (e.g. `store`) if you don't have one.
3. Click **Create** (or **Build a Database**).
4. Choose **M0 (Free)**, pick a provider/region close to you (e.g. AWS Mumbai `ap-south-1`), and give it a name (e.g. `store-cluster`).
5. Click **Create Deployment**.

### 2.2 Create a database user
1. A dialog asks you to create a database user. Otherwise go to **Security → Database Access → Add New Database User**.
2. Authentication method: **Password**.
3. Username: e.g. `store-app`.
4. Click **Autogenerate Secure Password** and **copy it somewhere safe**.
   - Autogenerated passwords only use letters and numbers. If you type your own, avoid `@ : / ? # [ ] %`, because these characters break the connection string unless URL-encoded.
5. Role: **Read and write to any database**.
6. Click **Add User**.

### 2.3 Allow Vercel to connect
Vercel Functions don't have fixed IP addresses, so Atlas must accept connections from anywhere. Your data is still protected by the username and password.

1. Go to **Security → Network Access → Add IP Address**.
2. Click **Allow Access from Anywhere** (this fills in `0.0.0.0/0`).
3. Click **Confirm**. Wait until the status shows **Active** (about a minute).

### 2.4 Copy the connection string
1. Go to **Database → Clusters** and click **Connect** on your cluster.
2. Choose **Drivers** → Driver **Node.js**.
3. Copy the connection string. It looks like:

   ```
   mongodb+srv://store-app:<db_password>@store-cluster.abcde.mongodb.net/?retryWrites=true&w=majority&appName=store-cluster
   ```

4. Make two edits:
   - Replace `<db_password>` with the password from step 2.2.
   - Add a **database name** after `.net/`. For example, `ecomm-store`:

   ```
   mongodb+srv://store-app:YOUR_PASSWORD@store-cluster.abcde.mongodb.net/ecomm-store?retryWrites=true&w=majority&appName=store-cluster
   ```

   This final string is your **`MONGO_URI`**. Without a database name, the data goes into a database called `test`.

## Step 3 — Generate the JWT secrets

Run this command **twice** and keep both outputs. You need two different values:

```bash
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

- First output → `ACCESS_TOKEN_SECRET`
- Second output → `REFRESH_TOKEN_SECRET`

Use new secrets for production. Don't reuse the ones in your local `.env`. Never commit them or paste them anywhere public.

---

## Step 4 — Deploy the backend

1. Go to https://vercel.com/new.
2. Under **Import Git Repository**, find your repo and click **Import**.
   - If it isn't listed, click **Adjust GitHub App Permissions** and give Vercel access to the repository.
3. Configure the project:
   - **Project Name:** e.g. `store-api`. This becomes part of the URL: `store-api.vercel.app` if it's available.
   - **Root Directory:** click **Edit**, select **`backend`**, click **Continue**.
   - **Framework Preset:** Vercel should detect **Express** automatically. If it shows something else, select **Express**.
   - **Build and Output Settings:** leave all defaults. The API needs no build step.
4. Open **Environment Variables** and add these five, one at a time:

   | Key | Value |
   |---|---|
   | `NODE_ENV` | `production` |
   | `MONGO_URI` | your connection string from Step 2.4 |
   | `ACCESS_TOKEN_SECRET` | first secret from Step 3 |
   | `REFRESH_TOKEN_SECRET` | second secret from Step 3 |
   | `CLIENT_URL` | `https://placeholder.example.com` (temporary; you'll replace it in Step 7) |

   `CLIENT_URL` must have *some* value now, because the API refuses to start if it's missing. You'll set the real frontend URL after the frontend exists.

5. Click **Deploy** and wait for **Congratulations!** (about 1 minute).
6. Click **Continue to Dashboard**. Under **Domains**, copy the production URL, e.g. `https://store-api-xyz.vercel.app`. This is your **backend URL**.

### Check the backend
Open these in your browser (use your own URL):

- `https://store-api-xyz.vercel.app/api/health` → should show `{"status":"ok"}`
- `https://store-api-xyz.vercel.app/api/products` → should show `{"products":[]}`

If the second one shows `{"products":[]}`, the API is connected to MongoDB Atlas. If it shows an error or times out, see [Troubleshooting](#troubleshooting).

### (Recommended) Set the Node.js version
Go to **Settings → Build and Deployment → Node.js Version** and choose **22.x** or newer. Then redeploy (see Step 7.2 for how).

---

## Step 5 — Point the frontend proxy at your backend

1. Open `frontend/vercel.json` and replace `YOUR-BACKEND-PROJECT.vercel.app` with your backend domain from Step 4.6:

   ```json
   {
     "$schema": "https://openapi.vercel.sh/vercel.json",
     "rewrites": [
       {
         "source": "/api/:path*",
         "destination": "https://store-api-xyz.vercel.app/api/:path*"
       },
       {
         "source": "/(.*)",
         "destination": "/index.html"
       }
     ]
   }
   ```

   - The **first rule** forwards `/api/...` to the backend.
   - The **second rule** sends every other path (like `/products` or `/login`) to `index.html`, so React Router can handle it. Without it, refreshing the page on `/products` would show a Vercel 404. Real files such as JavaScript bundles and the favicon are still served normally, because Vercel checks for a matching file before applying rewrites.

2. Commit and push:

   ```bash
   git add frontend/vercel.json
   git commit -m "Point frontend API proxy at deployed backend"
   git push
   ```

   This push also redeploys the backend automatically. That's harmless.

---

## Step 6 — Deploy the frontend

1. Go to https://vercel.com/new again and **import the same repository** a second time.
2. Configure the project:
   - **Project Name:** e.g. `store`.
   - **Root Directory:** click **Edit**, select **`frontend`**, click **Continue**.
   - **Framework Preset:** **Vite** (detected automatically).
   - **Build Command:** `npm run build` (default)
   - **Output Directory:** `dist` (default)
   - **Install Command:** `npm install` (default)
3. Open **Environment Variables** and add:

   | Key | Value |
   |---|---|
   | `VITE_API_URL` | `/api` |

   It is **`/api`**, not the full backend URL. Requests go to the frontend's own domain and the proxy from Step 5 forwards them. Vite bakes this value into the JavaScript at **build time**, so if you ever change it, you must redeploy.

4. Click **Deploy** and wait for it to finish.
5. Copy the frontend's production URL from the dashboard, e.g. `https://store-xyz.vercel.app`. This is your **frontend URL**.

---

## Step 7 — Connect the backend to the frontend URL

### 7.1 Update `CLIENT_URL`
1. Open the **backend** project in Vercel → **Settings → Environment Variables**.
2. Find `CLIENT_URL`, click **⋯ → Edit**, and set it to your frontend URL:

   ```
   https://store-xyz.vercel.app
   ```

   Use `https://` and **no trailing slash**.
3. Click **Save**.

### 7.2 Redeploy the backend
Environment variable changes only apply to **new** deployments:

1. Backend project → **Deployments** tab.
2. On the latest production deployment, click **⋯ → Redeploy → Redeploy**.
3. Wait for it to finish.

## Step 8 — (Optional) Add sample products

The seed script inserts 10 products with real photos, but only if the catalog is empty. Run it from your computer against the Atlas database:

```bash
cd backend
MONGO_URI="mongodb+srv://store-app:YOUR_PASSWORD@store-cluster.abcde.mongodb.net/ecomm-store?retryWrites=true&w=majority" npm run seed
```

The `MONGO_URI` given on the command line overrides the one in your local `.env` for this one command.

On Windows PowerShell:

```powershell
$env:MONGO_URI="mongodb+srv://..."; npm run seed
```

## Step 9 — Verify everything works

Open your **frontend URL** and go through this checklist:

- [ ] `/products` redirects to the login page
- [ ] **Register** a new account → you're sent to login with a success message
- [ ] **Login** → the products page loads
- [ ] **DevTools → Application → Cookies** → your frontend domain has a `refreshToken` cookie with **HttpOnly** ✓, **Secure** ✓, **SameSite** `None`, **Path** `/api/auth`
- [ ] **Reload the page** → you stay logged in (the refresh cookie works)
- [ ] **Add**, **edit** and **delete** a product
- [ ] Open **Profile** → your name and email are shown
- [ ] Refresh the browser while on `/profile` → the page loads (no Vercel 404)
- [ ] **Logout** → you're sent to login, and reloading doesn't log you back in
- [ ] Try it on your phone

In the DevTools **Network** tab, API requests should go to `https://store-xyz.vercel.app/api/...` (your frontend domain), **not** the backend domain.

Finally, update the two placeholders in `README.md`:

```markdown
## GitHub Repository
https://github.com/<your-username>/ecomm-sheryians

## Live Project
https://store-xyz.vercel.app
```

Commit and push.

## After deployment

- **Automatic deploys:** every `git push` to `main` redeploys both projects to production.
- **Preview deployments:** pushing another branch or opening a pull request creates preview URLs for both projects. The frontend preview still proxies to the **production** backend (the URL in `vercel.json`), so it uses the production database.
- **Logs:** backend project → **Logs** tab (or **Deployments → a deployment → Functions/Runtime Logs**). Server errors (500) are printed there. Passwords and tokens are never logged.
- **Custom domain (optional):** frontend project → **Settings → Domains → Add**. Afterwards, update `CLIENT_URL` in the backend to the new domain and redeploy the backend.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `/api/products` on the backend takes ~10s then returns a 500 | Atlas is blocking the connection | Atlas → **Network Access** must include `0.0.0.0/0` with status *Active* |
| Backend logs show `bad auth : authentication failed` | Wrong password in `MONGO_URI`, or unencoded special characters | Reset the database user's password to an autogenerated one and update `MONGO_URI`, then redeploy |
| Backend logs show `Missing required environment variables: …` | A variable wasn't added, or was added after the last deploy | Add it in **Settings → Environment Variables**, then **Redeploy** |
| Backend logs show `ACCESS_TOKEN_SECRET and REFRESH_TOKEN_SECRET must be different` | Same value used twice | Generate a second secret (Step 3) |
| Frontend is a blank page; the console says `VITE_API_URL is not set` | Frontend env var missing at build time | Add `VITE_API_URL=/api` to the **frontend** project and redeploy |
| API calls return **404** with Vercel's HTML page, or the `index.html` content | `vercel.json` still has `YOUR-BACKEND-PROJECT`, or the backend URL is wrong | Fix the destination in `frontend/vercel.json`, commit and push |
| Refreshing `/products` shows a Vercel 404 | SPA fallback rule missing | Make sure the second rewrite (`"/(.*)" → "/index.html"`) is in `frontend/vercel.json` |
| Browser console shows a **CORS** error | `VITE_API_URL` is set to the full backend URL instead of `/api` | Set it to `/api` and redeploy the frontend |
| Login works but you're logged out after every reload | Same cause as the CORS row: the cookie is being set on the backend domain | Use `VITE_API_URL=/api` so requests go through the proxy |
| `Too many attempts. Please try again in 15 minutes.` | 20 failed login/register attempts in 15 minutes | Wait, or see the rate-limit note below |
| Deploy fails while building `bcrypt` | Unusual Node version | Set the Node.js version to 22.x (Step 4) and redeploy |

## Deploying with the Vercel CLI instead (optional)

If you prefer the terminal to the dashboard:

```bash
npm install -g vercel
vercel login

# Backend
cd backend
vercel link                     # create/link the project; answer the prompts
vercel env add NODE_ENV production
vercel env add MONGO_URI production
vercel env add ACCESS_TOKEN_SECRET production
vercel env add REFRESH_TOKEN_SECRET production
vercel env add CLIENT_URL production
vercel --prod                   # prints the backend URL

# Frontend (after editing frontend/vercel.json with the backend URL)
cd ../frontend
vercel link
vercel env add VITE_API_URL production    # enter: /api
vercel --prod                   # prints the frontend URL

# Then set CLIENT_URL to the frontend URL and redeploy the backend
cd ../backend
vercel env rm CLIENT_URL production
vercel env add CLIENT_URL production
vercel --prod
```

`vercel env add` asks for the value interactively, so secrets don't end up in your shell history.

## Known limitations on Vercel

- **Cold starts:** after a period of no traffic, the first API request can take a second or two while the function starts and connects to MongoDB. Later requests reuse the connection.
- **Rate limiting:** the login/register limiter stores its counts in memory. On Vercel each function instance has its own memory and instances come and go, so the limit is approximate. It still slows down basic password-guessing. For a strict limit you would need a shared store such as Redis (e.g. Upstash).
- **Free-tier sleep:** an M0 Atlas cluster is paused after 60 days without any connections. Resume it from the Atlas dashboard if that happens.
